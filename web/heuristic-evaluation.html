VIP Photographer App: Demo Heuristic Evaluation

Nov 5, 2026 · Alan Porterfield

The demo is structurally sound and close to the HIG, but 21 problems need fixing before user testing: 4 major (unlabeled switches, no password recovery, silent loss of typed text, no Dynamic Type), 13 minor and 4 cosmetic. Checks covered 35 demo screen states and about 130 Figma frames in each of Light and Dark; section "Figma and demo compared" says which problems are in the design and which only in the demo.

Fix first

  1. Name every switch (#1). Seven switches (six on Notifications, one on Account) read as just "switch" to VoiceOver. Tie each to its row label.
  2. Add password recovery (#2). Sign in has no "Forgot password?" and the verification step has no alternate route. A photographer locked out on assignment day has no way back in.
  3. Stop silent loss of typed text (#3). Tapping outside any sheet closes it and discards what was typed. Confirm before discarding.
  4. Grow touch targets to 44 × 44 pt (#5). Chips are 36 pt, segmented controls 28 pt, and several buttons 34–43 pt. Extend hit areas without changing how they look.
  5. Fix contrast in the Figma tokens (#6, #19–21). Accent text on tinted buttons, destructive red in Figma, Dark-mode green text and one black placeholder fall below AA. Fixing the variables fixes the build too.

Proposal: Assignment header, before and after

Built as a separate page in the Figma file, "Proposal – Assignment header". The originals are untouched. The proposal puts the three secondary actions, Can't attend, Report issue and Timesheet, under one More menu. These actions are rarely used on the day of the assignment, so they should not take permanent space from the one action used every time, the primary button. This is based on anecdotal feedback from stakeholders; usage has not been measured.

What changes: (1) the header holds the type, status, then one row with the primary button and a 44 × 44 pt More button (accessible name "More actions"); (2) the More menu lists Can't attend, Report issue and Timesheet as 48 pt rows; (3) the Timesheet row card leaves the Details tab; (4) when the content scrolls, the header collapses to the primary row and the Details / Notes / Schedule control; (5) on the Notes tab, Add note (lead only) sits above the first note, where it can't fall below the fold.

Pinned header height on the S4 Details frame (874 pt screen, 95 pt tab bar), measured in Figma: before 350 pt (40%); with the menu 256 pt (29%); collapsed on scroll 218 pt (25%). Space left for content above the tab bar: 429 pt before, 523 pt with the menu, 561 pt scrolled. The menu keeps the header the same height at any Dynamic Type size, because the row holds only the primary button and a fixed icon button; the earlier visible-row version (318 pt, 224 pt scrolled) would grow as the secondary buttons wrapped.

Trade-offs: Can't attend and Report issue are time-sensitive, and they now take two taps and are not labelled on screen. Because they are rarely used on the day, that cost should fall on few people. If testing shows people can't find them, the fallback is the visible-row version, kept on the same Figma page as "ALT visible row". The first-time cost is discoverability: confirm in user testing that photographers find Can't attend in the menu.

Icons on the secondary actions

Each action carries the same SF Symbol in the menu and on the buttons, so it looks the same in both states: Can't attend is calendar.badge.minus, Report issue is exclamationmark.octagon (an exclamation inside a stop sign), and Timesheet is clock, matching the Timesheets tab. In the menu the symbol sits at the trailing edge, as in iOS menus, in the text color; on the buttons it leads the label, in the label color. The labels stay, so the symbols are decoration for VoiceOver (hidden), not the only cue. The demo draws look-alike SVGs; the native build should use the real symbols.

No primary button: show the actions

On a future-dated assignment there is no primary button, because Start Travel only appears on the day. The row would hold only the More button, so the two remaining actions, Can't attend and Report issue, show as two 44 pt buttons instead. There is no primary button for them to compete with, and a future assignment is when cancelling matters most. The cost is that the actions change from menu to visible between states. Once an assignment is fully done, with photos and timesheet submitted, no secondary actions remain and neither the menu nor the buttons appear.

Notes tab: Add note above the notes

The no-primary frames are on the same Figma page ("AFTER (no primary, future assignment)"). Not done: S2 (assignment day) has no menu frame yet, and no Dynamic Type frame at the largest size was built. The demo now shows the two buttons when there is no primary button, and has the More menu (primary button plus a 44 pt More button, menu rows 48 pt, Escape or any outside tap closes it) and Add note first on the Notes tab. The demo header also collapses on scroll: the type and status row scrolls away and the primary row and tabs stay pinned (measured in the demo: 249 px at rest, 215 px scrolled, on an 874 px screen). The collapse is live there, not an animation. The collapse is shown as a static scrolled frame, not an animation.

What works well

  • One rule for buttons. Short forms disable the primary until valid and explain why; long forms keep it enabled and show errors on tap (decision 101). Both behaviors are applied consistently.
  • One green action per screen. Secondary actions are chips or text, so the next step is obvious.
  • Safe destructive actions. Withdraw, Cancel Time Off and Sign out ask first, in red, with a clear Cancel.
  • Early arrival handled calmly. Arrival shows a banner, a reminder comes at start time, and only an early Start Assignment asks for confirmation.
  • Contacts are one tap. Each person shows name, role and number, and the whole row calls.
  • Every flow has a back step. Pushed Account screens and the timesheet edit form use the standard back button, and every form sheet has Cancel.

Coverage and limits

  • Evaluated: the demo built from the main branch, run locally in a desktop browser at phone size: 9 sign-in screens, Schedule (both tabs), Assignment Details (Details, Notes, Schedule), 10 sheets and action sheets, Time Off, Timesheets (list, entry, edit), Account, Appearance, Phone number, Change password, Notifications and the Sign out alert (35 states in all). Each state was captured in Light and Dark.
  • Method: scripted checks for touch-target size, text contrast, accessible names and font size in every state, then a look at the Light screenshots against Nielsen's 10 heuristics and the HIG. I did not look at the Dark demo screenshots; Dark was checked by measurement only. Figma was measured the same way (132 Light and 128 Dark phone-size frames): touch-target size by layer, contrast by fill values. I did not review the Figma screens for usability beyond that.
  • Not evaluated: VoiceOver on a device, Dynamic Type, real iOS controls (pickers, keyboard, haptics, swipe-down to dismiss), landscape and iPad, Android, slow or offline use, upload failure and notification-permission states and the live Vercel deployment.
  • Weight: one evaluator and no users. A heuristic evaluation usually uses three to five evaluators and finds roughly what an expert sees, not what a photographer in a gym at 7 a.m. struggles with.
  • Next step: fix the five items above, then test the Start Travel → Arrived → Start Assignment → Timesheet journey with five photographers, once on a real phone with the largest text size.
